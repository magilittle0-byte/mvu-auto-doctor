# 可版本化副本 / 场景规划

## 目的

副本不是固定剧本，也不能在目标已经达成后靠临时增加怪物无限续写。

本机制保存“当前世界中实际成立的场景结构”，同时允许玩家行动、世界支线、既有设定和系统规则通过可追溯因果改变它。玩家不知道幕后全貌，仍可自由选择路线、谈判、绕行、逃离、失败或提前解决问题。

## 数据结构

连续性账本 v5 在 `scenarioPlan` 中保存：

- `baseline`：不可覆盖的初始结构，包括主目标、完成/失败条件、原生终局冲突、路线、时限、赌注、阶段和收束状态。
- `baselineEvidence` / `baselineSourceRef`：建立基线所依据的 MVU、正文、角色卡或世界书事实，以及对应正文楼层。
- `current`：应用全部已接受修订后的当前有效版本。
- `amendments`：只追加、不回写的修订历史。
- `status`：`inactive / active / closing / completed / failed`。

`activeApex` 表示当前版本中的终局冲突或最高威胁，不等于所有副本都必须有 Boss。调查、谈判、求生等非战斗副本可以为空。

## 修订门禁

每条修订必须具备：

1. 稳定修订 ID。
2. `player_action / world_chain / setting_fact / system_rule` 原因类型。
3. 一个或多个稳定来源事件 ID。
4. 具体触发事实、作用机制和证据。
5. 每个变更字段的精确 `before → after`。
6. 结构变化需要明确列出仍然有效的既有成果。

本地代码重新计算 `current`，不相信模型直接返回的新当前值；基线不能被改写，前值不匹配、来源不存在、证据缺失或重复 ID 的修订会被拒绝。

`world_chain` 只能引用更新前已经存在且有进展、正文来源或已显现结果的事件。同一 AI 回复里刚刚临时生成的拦路怪、气氛、伏笔或“隐藏阶段”不能立刻被包装成长期世界因果来修改目标、通关条件或最终 Boss。

`player_action` 可以引用本回合新建的 `main_derivative` 事件，但该事件必须带有明确的行动父项；主回复自己新增的障碍不能冒充玩家选择。

## 允许的变化

所有规划字段都可合理修订。变化可以提高难度，也可以降低难度：

- 支线多轮推进后引入比原生终局更强的外部敌人；
- 玩家破坏关键设施，使原 Boss 失去力量或不再出现；
- 盟友行动打开捷径；
- 时间、资源、阵营或环境变化改写通关方式；
- 原目标失去意义，转为撤离、谈判或止损；
- 完成条件满足后进入收束。

修改主目标、完成/失败条件、终局冲突或收束状态时，必须保留并说明此前已经取得的战斗、探索、资源、承诺和阶段成果。已经击败的原 Boss 不得被无痕降格成“前菜”。

## 终态

当当前完成条件满足时，规划应进入 `ready` 或 `completed` 并写明收束依据。`completed` / `failed` 是不可复开的终态。

副本结束后仍在发展的敌人、政治影响、风声或环境后果，应建立新的世界事件并通过 `causedBy` 连接，而不是重新打开同一副本继续刷怪。

## 追溯方法

打开“世界动态 → 事件账本”：

1. “当前有效版本”显示主回复现在必须尊重的结构。
2. “初始基线（不可覆盖）”显示副本生成时的原始目标和终局。
3. “可追溯修订”显示来源事件、触发、作用机制、证据、字段前后值、保留成果和对应正文楼层。
4. 再展开来源事件卡，可继续检查事件的 `seedBasis`、`causedBy`、进展、传播节点和正文来源。

若当前版本发生变化但没有修订记录，或修订找不到来源事件/正文楼层，即为缺陷。

## 必测回归

- 旧版 continuity v4 存档升级到 v5 时保持原事件与世界状态，规划默认为未建立。
- 有边界场景可以建立一次完整基线。
- 更新前已存在的成熟世界支线可以修改终局威胁。
- 同回合临时生成的威胁不能用 `world_chain` 修改终局。
- 模型直接重写 `baseline` 或 `current` 不生效。
- 结构变化缺少 `preserves` 时不生效。
- 可合理移除 Boss、降低难度或改变路线，不只允许升级。
- `completed` / `failed` 规划不能复开。
- 基线和每条修订都有正文来源指针。
- 正文注入要求达到完成条件后收束，禁止临时追加“真正最终 Boss”。
- 390×844 下规划卡和修订入口不小于 42px，并且内容无横向溢出。

正式推送仍必须遵守 [真实环境 QC](./REAL_ENV_QC.md)。
