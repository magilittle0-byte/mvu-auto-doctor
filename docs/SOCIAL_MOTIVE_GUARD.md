# 人物动机、自主性与关系证据守卫

## 目标

本模块解决的是跨层污染，不是把跑团统一改成光明或温暖题材：

```text
主模型无依据补写玩家隐藏动机
→ 正文把NPC推向极端反应
→ MVU固化好感/依赖/崇拜/服从
→ 活世界、数据库与后续正文继续引用
→ 错误解释形成自我强化
```

修复后的链路：

```text
当前动机合同
→ 未选候选隔离
→ 风险识别
→ 轻量语义二审
→ 仅放行/撤回本轮关系路径
→ 写前日志、回读、追溯与撤销
```

## 三层职责

### 1. 主正文合同

`socialNarrativeGuardEnabled` 默认开启。每次真实生成开始时，扩展使用系统角色注入：

- 当前用户明确动机优先；
- NPC怀疑是有限视角，不是旁白事实；
- 普通照顾可以不改变关系；
- 强烈情绪需要刺激、阈值与恢复空间；
- 强制状态与自愿态度分开；
- 人物保留自己的目标、边界、习惯与信息局限；
- 明确黑暗选择照常生效，不做洗白；
- 直接承接当前输入，不先机械复述上一轮。

该层影响主模型如何写，不调用额外模型。

### 2. 未选候选隔离

在 `CHAT_COMPLETION_PROMPT_READY` 中，仅处理 `role=assistant` 的历史消息：

- 移除完整或悬空的 `<options>`、`<branches>`；
- 不修改聊天存档与前端显示；
- 不修改 system 消息中的格式合同；
- 不修改 user 消息，因此用户实际点击、复制或改写后发送的选择仍是权威输入；
- 文本补全后端无法安全区分历史角色时不做正则删除，只依赖主合同。

变量审计、活世界和论坛使用的内部剧情摘要也调用同一隔离函数。

### 3. 人物关系二审

`socialAuditMode`：

- `off`：关闭二审；正文合同可独立保留。
- `balanced`：默认。关系变化、极端标签、玩家隐藏动机归因或强制/自愿冲突才调用。
- `strict`：所有关系变化都调用；用于大修QC或定向排查。

二审输入只有：

- 本轮用户实际输入；
- 本轮AI正文（已去机制与未选候选）；
- 最多五条相关历史；
- 本轮发生变化的关系路径及前后值；
- 触发原因。

二审输出是 JSON。对每条已知关系路径只能选择：

- `allow`：证据足够，保留变化；
- `revert`：证据不足或强制/自愿混淆，恢复本轮前状态。

模型不能：

- 发明新路径；
- 给出替代关系值；
- 改写正文；
- 调整剧情基调；
- 因自身温暖倾向撤销有证据的黑暗后果。

## 失败与费用边界

- 单次输出上限默认 1024 tokens。
- 平衡模式每个回复最多一次社会语义审核。
- 网络、解析或费用硬上限导致结果不确定时，有争议的持久关系恢复到本轮前状态并标记待确认。
- 默认月度软提醒 ¥5，不降级。
- 默认月度硬上限 ¥10，可配置。
- 费用按返回 usage 记录；服务不返回 usage 时，用字符数保守估算并标记 `estimated=true`。
- 聊天元数据只保存结构化结论、路径、来源和usage，不保存原始模型输入、输出、密钥或完整私聊。

## 如何追溯

设置页打开“人物动机、自主性与关系二审”：

1. 查看来源楼层。
2. 查看触发原因与总结。
3. 查看每条关系路径的 `allow/revert`。
4. 若发生回退，当前 swipe 末尾会有对应 `<UpdateVariable>` 纠错块。
5. 最近修复日志保存写前快照和触碰路径，可使用现有“撤销上次修复”恢复。
6. 脱敏诊断包包含结论、路径、usage和回退状态，不包含正文或提示词原文。

脚本接口：

```js
await MvuAutoDoctorAPI.auditSocialRelations();
MvuAutoDoctorAPI.getSocialAudits();
MvuAutoDoctorAPI.getSocialPromptSanitization();
```

## 验收原则

DeepSeek不能作为正文改善的唯一证据。真实QC必须：

- 用同一个主正文模型、同一聊天基线和同一组输入做合同开/关消融；
- DeepSeek只保持为二级审核器；
- 同时回放固定的恶意极端输出，证明本地隔离和关系回退起效；
- 用明确威胁或强制能力反例证明合法黑暗内容不会被二审的温暖倾向抹掉。

完整流程见 [`REAL_ENV_QC.md`](REAL_ENV_QC.md) 的 5B。
