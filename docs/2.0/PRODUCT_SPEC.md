# MVU Auto Doctor 2.0 产品规格

状态：`2.0-phase0`

产品定位：共创式跑团运行层

目标版本：2.0.0；远期边界：2.1

## 1. 产品定义

MVU Auto Doctor 2.0 不是“更严格的变量修复器”，而是位于玩家、叙事模型、角色卡规则、MVU状态与下游插件之间的共创式跑团运行层。

它默认相信桌上会有口胡、即兴创造、意外路线和不完整信息。系统先让叙事自然发生，再用少数硬边界保护：

- 玩家重大行动权；
- 资源、物品、技能、任务与关系的事务一致性；
- regenerate、swipe、continue 和派生分支之间的隔离；
- 变量结构、读写回读和兼容迁移；
- 事实与角色知识的证据边界；
- 长任务的可观察性、可取消性和有界存活。

自然语言是第一入口，UI 是同能力的可见、可审计入口。任何核心操作都不得只存在于表单，也不得只存在于无法发现的自然语言暗号里。

## 2. 目标

2.0.0 必须做到：

1. 玩家可以用普通话描述行动、主张世界细节、提出临时方案或要求 UI 操作，不必先填写结构化表单。
2. 导演层能区分叙事补白、合理口胡、优势口胡和改写性口胡，并给出与风险相称的裁定。
3. 未经授权不得替玩家新增移动、决定、对白、技能、资源消费、检定、语气、态度或心理。
4. 一次生成对应一个可追踪分支与消息指纹；旧分支的异步结果、资源结算、任务和数据库读取不能落入新分支。
5. 物品、装备、技能、事实、知识、关系、任务与事务有通用 V2 数据合同，同时保留开放叙事扩展。
6. 正文修复、状态提交和下游读取有明确顺序；数据库只能读取已稳定的最终正文。
7. 真实历史事故能以小型脱敏 fixture 重放，并逐步升级为自动化行为验收。
8. 1.x 聊天和状态可以惰性读取、可逆迁移和降级展示，不因升级丢失旧字段。

## 3. 非目标

2.0.0 不负责：

- 把所有跑团决策变成审批流、对话框或表单；
- 判断文风好坏、剧情是否“温暖”、奖励是否足够慷慨；
- 用禁词正则代替语义裁决；
- 猜造卡片没有声明的装备槽位、药剂数值、技能消耗或掉落公式；
- 把“无限回廊”或任何单一卡片的变量路径当成产品唯一结构；
- 自动确认用户随口说出的暗号、传闻、猜测或未选择候选为世界事实；
- 自动合并彼此冲突的分支；
- 在阶段0大规模重构现有生产运行时；
- 读取、保存或提交 API 密钥、完整私人聊天、Cookie、浏览器档案或外部站点凭据。

## 4. 设计原则

### 4.1 叙事优先，规则兜底

系统允许模型补足环境、NPC反应、感官细节和非关键过渡。只有触及硬边界时才中断、降级、要求检定或创建事务。缺少证据时优先保持未知、候选或原值，不用常识补成确定状态。

### 4.2 玩家行动权是负授权边界

“没有说可以做”不等于禁止所有叙事，但明确的“不移动”“只说这一句”“不补心理”等约束是本轮最高权威。导演层必须同时保留正授权和负授权，不能只抽取玩家想做什么。

### 4.3 开放叙事，硬字段承载可结算部分

描述、风味、来源传说、外观和局部世界语义允许开放扩展；数量、资源变化、槽位、消耗、事实状态、知识范围、任务状态、分支与事务身份必须进入硬字段。叙事文本不能替代可结算字段。

### 4.4 事实与知识分离

“某事为真”和“某角色知道某事”是两个模型。玩家输入、NPC怀疑、论坛流言和模型提案默认不是已确认事实；事实确认也不会自动让所有角色知情。

### 4.5 状态变化必须可追踪、幂等、可回读

每次资源或结构变化必须有分支、消息指纹、幂等键、前置条件、写入集合与结果。相同幂等键在同一分支最多提交一次；目标变化后迟到结果必须成为 `stale`。

### 4.6 分支是隔离域

swipe、regenerate 和显式分叉产生新的分支身份。旧分支事实、事务、任务与下游读取不能自动泄漏；合并只能由未来明确协议执行，2.0.0 不做隐式分支合并。

### 4.7 语义裁决可解释，正则只做召回

正则可以发现“可能存在风险”的候选，但不能独立确认动机、关系、事实或口胡等级。最终裁决必须依赖结构化上下文、证据和有界语义判断。

### 4.8 自然语言与 UI 同权

自然语言命令与 UI 操作最终都生成同一类领域命令、事务和审计记录。UI 不得绕过事务协议；自然语言也不得绕过危险操作确认、分支身份或写后回读。

## 5. 导演模式

“导演模式”是每轮的协调流程，不是把玩家变成填表人。默认流程：

1. 捕获当前 `MessageFingerprint`、分支和上一稳定状态。
2. 从用户输入抽取已授权行动、明确负约束、世界主张和希望获得的优势。
3. 对主张进行口胡四级分类；对事实、知识、资源或关系影响建立候选，不直接落地。
4. 允许叙事模型在边界内生成；NPC、环境和世界可以自主反应。
5. 对硬字段变化建立 `Transaction`，执行前置条件、分支、幂等和结构验证。
6. 仅对命中风险的内容运行定向语义复核；不得借复核改写整体文风。
7. 先完成正文修复，再提交状态；写后回读通过后发布“最终正文稳定”屏障。
8. 数据库、论坛索引、记忆与其他下游只能在屏障后读取。
9. 任一异步边界重新核对消息指纹；失配即标记 `stale`，不得尝试“落到最新楼层”。

导演反馈有三种可见度，但硬边界不变：

- `沉浸`：默认只在需要检定、付代价、冲突或失败时提示。
- `可审计`：显示口胡等级、证据、事务和分支状态。
- `调试`：额外显示指纹、幂等键、看门狗和迁移诊断；不显示密钥或完整私有上下文。

## 6. 口胡四级

口胡等级评估的是主张对既有事实和可结算优势的影响，不是评判玩家“说得好不好”。

| 等级 | 名称 | 定义 | 默认裁定 | 状态处理 |
| --- | --- | --- | --- | --- |
| H0 | 叙事补白 | 只增加外观、语气环境、无机械收益的小细节，且不与锚点冲突 | 直接接受 | 可留在正文；无需事实账本，除非后续被引用 |
| H1 | 合理口胡 | 符合场景常识、低影响、无现成冲突的局部事实或便利 | 接受，必要时声明范围 | 提交为当前分支的低影响事实，并保留来源 |
| H2 | 优势口胡 | 会获得通行、情报、资源、减免、战术位置或显著成功概率 | 要求检定、代价、折算或有限接受 | 结果前保持候选；成功后通过事务提交 |
| H3 | 改写性口胡 | 否定已确认事实、已结算事务、终态任务或分支历史 | 默认拒绝；只有显式重写授权才可新建分支 | 不覆盖当前分支；显式重写必须产生新分支和审计记录 |

补充规则：

- 同一句话可以包含多个主张，按最高影响部分拆分裁定，不能整句一刀切。
- “听起来像暗号”不能把随机字符串提升为秘密协议事实。
- H2 允许导演给“是，但……”的折算，不等于强制拒绝创造。
- H3 的显式重写不是普通事务回滚；必须保留原分支并建立新的分歧点。
- 分类不能仅依赖关键词；`REAL_REPLAY_ACCEPTANCE_MATRIX.md` 中的三个口胡用例是最低验收基线。

## 7. 核心模块

### 7.1 Turn Boundary

维护本轮正授权、负授权、用户主张、候选事实和允许的自然叙事空间。输出供主模型、修复器和审计器共同使用。

### 7.2 Claim Adjudicator

完成口胡四级分类、证据检索、裁定与可解释结果。H2/H3 必须能生成检定、代价或分支命令，而不是只返回一段建议文字。

### 7.3 Fact & Knowledge Ledger

分别维护事实状态、证据、分支范围，以及角色/群体的知情层级。论坛猜测、NPC怀疑和用户测试口令不得直接写成 confirmed/verified。

### 7.4 Transaction Kernel

统一资源、物品、装备、技能、关系、任务和正文稳定屏障的 prepare/commit/abort/rollback/stale 生命周期，负责幂等、前置条件、写入队列和回读。

### 7.5 Branch Manager

管理 regenerate、swipe、continue、显式分叉和弃用分支；为事务、事实、任务和下游读取提供隔离域。

### 7.6 Domain Models & 1.x Adapters

提供 ItemV2、EquipmentV2、SkillV2、SocialState、Quest 等通用模型，并从1.x自由对象安全映射。无法证明的字段进入待确认状态，不能猜值。

### 7.7 Narrative & Social Guard

保护玩家行动权、强制/自愿关系分离、有限视角和未选候选隔离。只回退本轮违规路径，不洗白玩家明确选择的黑暗行为。

### 7.8 Task Runtime & Watchdog

所有长任务都有阶段、进度、心跳、软取消、硬超时、租约和终态。看门狗只能终止或隔离迟到结果，不能把不确定结果写入新目标。

### 7.9 Dual Surface UI

提供自然语言命令对应的可见 UI：裁定卡、事务卡、分支状态、任务进度、撤销与证据入口。两种入口必须调用同一领域命令。

### 7.10 Replay & QC

读取脱敏 fixture，先做结构验证，随后逐阶段接入领域核、事务、浏览器和真实 SillyTavern 验收。模拟通过不能替代真实环境门。

## 8. 2.0.0 边界

2.0.0 包含：

- V2领域模型与1.x只读/惰性迁移适配；
- 消息指纹、分支隔离与事务内核；
- 口胡四级、玩家边界、事实/知识和社会关系裁决；
- 资源、物品、装备、技能、任务的类型化结算；
- 正文稳定屏障、下游等待和长任务看门狗；
- 自然语言/UI双入口；
- 本目录回放矩阵的自动化与真实环境验收。

2.0.0 不承诺自动合并冲突分支，也不承诺跨角色卡推断所有历史自由字段。

## 9. 2.1 边界

2.1 才考虑：

- 显式、可预览的分支合并与冲突解决；
- 多玩家并发行动和主持人权限；
- 跨聊天/跨世界的事实引用与知识迁移；
- 可视化导演时间线、事务图和因果图；
- 可安装的世界规则/槽位/资源命名适配包；
- 更丰富的H2折算策略和主持人自定义裁定模板；
- 经真实数据证明必要的性能优化与模块化重构。

## 10. 成功指标

2.0.0 发布前至少满足：

- 阶段0所有 fixture 已转为自动行为测试并通过；
- 玩家明确负约束违规率在回放集中为0；
- 同一幂等键在同一分支重复资源结算为0；
- 弃用分支的迟到写入和下游读取为0；
- 无证据随机口令被确认为世界事实为0；
- 强制状态导致自愿好感/信任自动上升为0；
- 已声明机械效果的物品/技能不存在纯文本不可结算状态；
- 超时任务在看门狗期限内进入可见终态；
- 真实 SillyTavern 验收与自动模拟结论一致，差异必须阻断发布。
