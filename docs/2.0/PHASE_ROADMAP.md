# MVU Auto Doctor 2.0 阶段路线图

状态：`2.0-phase4`

交付纪律：一阶段一任务；每阶段必须使用 [`PHASE_HANDOFF_TEMPLATE.md`](PHASE_HANDOFF_TEMPLATE.md)

## 全局交接规则

每阶段必须：

1. 只从上一阶段已提交 SHA 开始，不依赖聊天记忆或未提交临时文件。
2. 先读本目录全部权威文件、上一阶段交接和当前 `git status`。
3. 保留用户已有修改，不用 reset/checkout 覆盖。
4. 只修改该阶段列出的生产范围；新增行为必须有对应 fixture 或测试。
5. 运行该阶段命令、既有相关回归、密钥/私人内容增量扫描和差异审计。
6. 记录提交 SHA、分支/PR、未决决策、已知风险和下一阶段准确入口。
7. 不以 README、截图或人工口头结论代替可执行完成门。

## 阶段1：V2领域核与协议验证器

输入：

- 阶段0提交 SHA；
- `PRODUCT_SPEC.md` 与 `DATA_TRANSACTION_PROTOCOL.md`；
- `replay-fixture.schema.json` 和全部结构测试。

范围：

- 实现无宿主依赖的 V2 类型归一化与验证器；
- ItemV2、EquipmentV2、SkillV2、Fact、Knowledge、SocialState、Quest；
- EvidenceRef、MigrationState 和开放 `extensions` 保留；
- 1.x对象到 V2 的纯函数只读适配器；
- 口胡四级的结构化结果类型，但不接主模型。

输出：

- 独立 `v2/domain/` 核心模块；
- 领域模型 schema/validator；
- 迁移诊断，不执行生产写入；
- 激活领域结构相关 fixture 的行为测试。

完成门：

- 未知旧字段往返不丢失；
- 药剂无数值、技能文本成本、装备错槽、强制/自愿关系用例按协议拒绝或 unresolved；
- 不硬编码单一卡片路径；
- 默认 `npm test` 无回归；
- 阶段1交接写明阶段2可复用的 API。

准确入口：

> 从 `DATA_TRANSACTION_PROTOCOL.md` 第2至9节实现纯函数领域核；首先让 `RR-ITEM-CONSUMABLE-EFFECT`、`RR-SKILL-TEXT-COST`、`RR-EQUIPMENT-SLOTS`、`RR-SOCIAL-COERCION-VOLUNTARY` 通过，不接触宿主写入。

## 阶段2：消息身份、分支与事务内核

输入：

- 阶段1领域核与交接；
- 现有1.x `targetIsCurrent`、写前日志、写后回读、撤销和分支 checkpoint 实现。

范围：

- MessageFingerprint、Branch、Transaction、幂等键；
- prepare/commit/abort/rollback/stale 状态机；
- 单写入队列、精确目标回读、路径级回滚；
- regenerate/swipe/continue 分支边界；
- 只提供宿主适配接口，不改 UI。

输出：

- `v2/transaction/` 与宿主桥接接口；
- 分支 checkpoint 迁移；
- 重Roll、迟到结果、并发和重复结算行为测试。

完成门：

- 同分支同幂等键最多提交一次；
- 旧分支事务不能写入当前分支；
- 回滚保留外部并发合法变化；
- `RR-FINGERPRINT-PREVIOUS-REPLY` 与 `RR-REROLL-IDEMPOTENCY` 自动通过。

## 阶段3：导演层、玩家边界、事实与知识

输入：

- 阶段2事务/分支 API；
- 产品规格的导演模式和口胡四级；
- 当前社会动机合同与连续性有限知识门。

范围：

- Turn Boundary；
- H0-H3 Claim Adjudicator；
- Fact/Knowledge 状态机；
- 随机口令、NPC怀疑、未选候选和玩家负约束；
- 风险召回与语义裁决分离。

输出：

- 可解释裁定对象；
- 主模型上下文合同；
- H2检定/代价命令与H3显式分支命令；
- 相关回放自动化。

完成门：

- `RR-AGENCY-NO-MOVE`、三类口胡、随机暗号和错误回复复用通过；
- 明确黑暗选择不被洗白；
- 无证据输入不升级 confirmed/verified；
- 不以禁词正则作为最终裁决。

## 阶段4：领域事务整合

输入：

- 阶段1领域核；
- 阶段2事务内核；
- 阶段3导演裁定。

范围：

- 物品使用、装备穿卸、技能成本、社会关系、任务终态；
- 复合事务与前置条件；
- 1.x真实状态惰性迁移；
- 未决/隔离数据的可见诊断。

输出：

- 领域命令到 Transaction effects 的适配；
- 完整1.x兼容回归；
- 任务取消/替代和资源单次结算。

完成门：

- 装备/技能/药剂/社会/任务 fixture 全部自动通过；
- 任一失败无部分写入；
- 旧数据不丢字段、不猜槽位、不猜数值；
- 真实5.4.1脱敏投影可完成只读迁移诊断。

## 阶段5：自然语言与 UI 双入口

输入：

- 阶段3导演命令；
- 阶段4领域事务；
- 当前设置页、悬浮面板和移动端交互基线。

范围：

- 自然语言命令与 UI 控件映射到同一领域命令；
- 裁定、事务、分支、证据、迁移缺口和撤销视图；
- 沉浸/可审计/调试可见度；
- 390×844 指针/触控/键盘可访问性。

输出：

- 双入口 UI；
- 移动浏览器回归；
- 不暴露私密事实、完整提示词或密钥的诊断。

完成门：

- UI 与自然语言产生等价命令和事务；
- 无危险操作绕过确认；
- Android 展开、触控尺寸、视口和焦点回归通过；
- 模拟 UI 通过不替代真实酒馆检查。

## 阶段6：稳定屏障、下游和真实回放自动化

输入：

- 阶段2事务/分支；
- 阶段5双入口；
- `REAL_REPLAY_ACCEPTANCE_MATRIX.md` 全部用例。

范围：

- 正文 repair → state commit → settled 顺序；
- 数据库/记忆/论坛下游等待；
- TaskLease、进度、软取消、看门狗；
- 结构 fixture 到集成/浏览器/真实环境回放的升级；
- SQL参数化、长度边界和并发兼容门。

输出：

- 兼容 API v4 或明确的 V2 barrier；
- 下游集成契约；
- 全矩阵自动化报告；
- 真实 SillyTavern QC 报告模板。

完成门：

- `RR-REPAIR-DB-BARRIER`、`RR-TASK-WATCHDOG`、数据库/Android/真实差异用例通过；
- 一小时级无人检查任务不再无终态；
- 数据库只读最终正文；
- 模拟与真实结论不一致时发布门失败。

## 阶段7：迁移、发布硬化与2.0.0候选

输入：

- 阶段1至6全部交接；
- 全部自动回放与真实环境报告；
- 公开发布清单。

范围：

- 1.x升级/降级演练；
- 性能、容量、隐私、安全、故障恢复；
- 打包、版本、CHANGELOG、用户文档；
- 同主模型开/关消融和真实长局；
- 发布候选，不自动合并 main。

输出：

- 2.0.0 RC；
- 迁移与回滚指南；
- 完整 QC 收据、SHA256 和可审阅 PR；
- 2.1 未决项清单。

完成门：

- 全部阶段0 fixture 已有自动行为层且通过；
- 全套既有测试和真实 QC 通过；
- 密钥/私人内容扫描为0；
- 1.x聊天升级后可读、失败可回退；
- 分支/事务/下游/看门狗指标达到 `PRODUCT_SPEC.md` 成功标准；
- 由维护者审阅 PR 后再决定合并，不直接推 main。

## 阶段边界表

| 阶段 | 生产运行时可写范围 | 首要风险 | 下一阶段依赖 |
| --- | --- | --- | --- |
| 1 | 无宿主写入，纯领域函数 | 过拟合单一卡片 | 稳定 V2 API |
| 2 | 事务/分支桥接 | 重复或串分支写入 | 幂等与指纹 |
| 3 | 导演上下文与裁定 | 语义过度拦截 | 可解释命令 |
| 4 | 领域复合事务 | 半提交/猜值 | 原子效果 |
| 5 | UI与自然语言入口 | 两套逻辑漂移 | 同一命令总线 |
| 6 | 下游与任务运行时 | 抢跑/僵尸任务 | settled与lease |
| 7 | 迁移与发布 | 私密泄漏/不可回退 | 全门通过 |
