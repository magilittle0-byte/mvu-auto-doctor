# MVU Auto Doctor 2.0 迁移与回滚指南

适用候选：`2.0.0-rc.1`

## 迁移原则

2.0 不批量重写旧聊天。首次读取 1.x 数据时，医生建立只读 V2 sidecar 投影；1.x
聊天仍是可读回退源，未知作者字段保留在 `extensions.legacy`，歧义数值、槽位、
资源、关系和任务状态显示为 `unresolved` 或 `quarantined`，不会被猜测或结算。

升级前请保留原聊天备份。升级演练会核对聊天摘要、对象数量和序列化容量，生成迁移
诊断与回滚收据，但不会把诊断当作生产写入。只有 `valid/mapped` 记录可进入 V2
事务；其余记录继续以 1.x 只读形式显示。

## 升级演练

1. 在设置页环境自检确认 API v4、持久存储、精确读写和保存回调均可用。
2. 对选定聊天执行只读迁移诊断，检查 `mapped/unresolved/quarantined` 计数。
3. 确认旧聊天正文、swipe、未知扩展字段和原有 1.x 状态仍可读取。
4. 只对 mapped 记录启用 V2 sidecar；不得把 unresolved 记录手工改成已结算。
5. 刷新并重载同一聊天，确认 barrier、幂等、恢复和最终指纹仍可读取。

自动演练入口是 `prepareLegacyUpgradeDrill()`。默认上限为 256 条领域记录和 8 MiB
聊天投影；该边界已用用户授权的57消息、3,321,711字节更新前真实记录做只读演练，
迁移和摘要回滚均通过。超过上限仍会进入 `fallback`，保留旧聊天，不产生部分 V2
sidecar。

## 回滚

回滚必须使用升级演练生成的只读快照与 SHA-256 摘要：

1. 停止对目标聊天的新 V2 事务，并等待当前任务进入终态。
2. 核对聊天、消息、swipe、generation、branch 和内容指纹。
3. 调用 `rollbackLegacyUpgrade()` 验证快照摘要并移除 V2 权威 sidecar。
4. 恢复 1.x 只读视图；不得删除未知旧字段或物理删除审计记录。
5. 若已有事务写入，使用阶段2/6恢复记录，只恢复仍等于本事务写后值的路径。
6. 重新加载聊天并确认正文、旧字段、论坛/连续性计数和当前分支可读。

摘要不匹配、身份歧义、目标已切换或当前路径被合法外部更新时，自动回滚必须停止；
保留恢复记录，转人工审阅，禁止覆盖最新楼层。

## 降级边界

降级后可以读取 1.x 聊天和旧扩展字段，但 2.0 独有的分支、事务、事实/知识、
TaskLease 和 barrier 只作为审计 sidecar 保留。1.x 不会执行这些 V2 记录，也不会
隐式合并分支。维护者确认回滚结果前，不应删除 V2 审计数据。
