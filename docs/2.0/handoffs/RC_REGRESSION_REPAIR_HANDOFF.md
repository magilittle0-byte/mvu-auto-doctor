## 生产修复

1. 唯一无歧义的缺失 `</content>` 在本地恢复为新 swipe，原消息不覆盖。
2. 所有完整旧 UpdateVariable 块归一为一个最终块，防止重载重复应用。
3. 自动终态失败按完整目标去重，模型调用硬上限180秒；手动重试仍可用。
4. 新旧 TavernHelper 脚本容器和嵌套组统一抽取，兼容5.5.3与旧档。
5. 追加 swipe 前归一 `swipe_info`，避免身份数组错位。
6. 修复 SillyTavern 宿主 CSS 对 `[hidden]` 和 `width:min-content` 的覆盖。
7. 广度遍历由 `shift()` 改为索引游标，减少长档案中的数组搬移。
8. 医生创建的修正版 swipe 不再触发用户 swipe 回滚；最终 barrier、连续性和论坛显式
   跟随修正版 `finalTarget`，而真正的 regenerate/swipe/chat switch 仍严格 stale。
9. 浮层根背景改为实色，避免高密度角色卡正文在手机上干扰医生文本。
10. 同一完整目标在创建新 barrier 前复用已有 pending/terminal 记录；5次并发
    `MESSAGE_RECEIVED` 不再制造重复结算或重复模型风暴。
11. Actor Shard 严格输出示例改为候选事实的实际值，不再用白名单外占位符；真实
    1/3/5 worker 分别1/1、3/3、5/5成功。
12. 通用兼容边界固定为动态 JSON Pointer、实际 MVU 数据和宿主生命周期。当前卡、
    当前表格、骰子 UI 与缝合标签都不是核心前提；未知模板保守跳过专项方言判断。
13. 自检新增“数据库遗留兼容层”判定：只有同时发现作者 bundle 下载、源码字符串
    改写和医生 barrier 注入才报错。干净作者加载器仍是普通非托管第三方，不要求协议。
14. 关系二审不再用第二次模型调用修 JSON。缺失逗号和尾逗号由本地安全修复；截断或
    其他不确定结构立即回滚关系变化并待确认，不猜语义。

## 真实数据库与通用性证据

- 用户当前报告对应的真实加载器并非作者短入口：它固定 `spv8.4`，先下载作者 bundle，
  再用精确源码片段替换注入医生等待逻辑。`spv8.7.4` 相对该版本已前进60提交并重构
  update orchestrator、写事务、checkpoint、迁移和 chat service；旧替换层失配是本次
  “更新后完全加载不了”的首要责任边界。
- 新探针使用全新空白数据根，只装 TavernHelper 运行时、当前医生和用户提供的作者
  原版导入脚本；没有复制 settings、聊天、角色或凭据。脚本仅在内存指向
  `spv8.7.4`。初次加载与整页重载均收到官方 HTTP 200 和正确版本响应头，数据库
  API 两次均为116个方法，公开更新入口返回真值对象，UI 两次挂载，医生/数据库
  归属错误均0；临时数据和8011已清理。
- 安全更新方式：先导出/备份数据库，停用并移除旧“源码改写兼容层”，重新导入作者
  当前原版数据库本体并按作者标题填 `spv8.7.4`，刷新后先确认数据库独立加载，再启用
  医生。若医生自检仍出现“数据库遗留兼容层”，不要继续覆盖更新；它说明旧脚本仍在。

- 隔离 settings 已先备份，只安装当前安全入口 spv8.4；公开
  `AutoCardUpdaterAPI` 114个方法可见。结构发现式最小 CRUD、刷新、两类回调、设置
  UI、切聊、保存、重载和清理通过，导出哈希在切聊/重载后一致。
- legacy spv5.5.6 单独复验同一流程，88个方法；只作为兼容样本，不作为生产结论。
  复验后恢复 spv8.4，没有并发安装两个数据库入口。
- 医生生产代码不读取表名、列名、行号或数据库 DOM，也不调用数据库 CRUD/API。
  无合作协议时准确显示 `unmanaged/unknown/info`，不伪称外部强一致。
- 随机表名/列名、未知前端对象和陌生英文 `nebulaLedger` Schema 回归证明：医生
  外部函数调用0、未知状态重塑0。5.5.3只是一套 fixture，不是产品适配范围。
