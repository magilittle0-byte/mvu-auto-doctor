# MVU 自动医生 2.0 RC 使用说明

适用版本：`2.0.0-rc.1`

这是供候选测试使用的用户说明。当前版本仍在独立 Draft PR 中，尚未合并
`main`。酒馆只能在线安装或更新时，请让扩展管理器取得候选分支；仓库地址不变，
但不能把分支留空，否则会取得 `main` 上的稳定版而不是本候选。

## 1. 从现有1.x在线升级

1. 用酒馆自己的聊天导出/备份功能保存要测试的长聊天，并等待当前自动医生任务
   结束；聊天、角色卡、数据库和其他脚本保持原位。
2. 打开“扩展/已安装的扩展”，找到“MVU 自动医生（通用）”这一行。
3. 点击该行的分叉/分支图标（你截图中名称右侧第一个树枝形按钮），等待在线分支
   列表加载完成。
4. 选择并确认：

   ```text
   origin/codex/v2.0-phase7-release-candidate
   ```

   必须选带 `origin/` 的候选项；不要选择 `main`。酒馆会在线获取远端候选并把
   现有医生安装切换到该分支，不需要导入 ZIP，也不需要删除扩展。
5. 刷新酒馆，扩展信息应显示 `2.0.0-rc.1`。如果该行仍显示“可更新”，再点一次
   更新并刷新；以后普通“更新”会继续跟随这个候选分支。
6. 打开自动医生设置，先运行环境自检，再检查严格变量通道和轻量通道所选的
   API 预设、模型与代理方式。两个通道可以共用一个连接，也可以分开配置。
7. 确保只有一个自动变量修复器负责写入。自动医生会尝试关闭兼容
   Story Oracle 的 `AUTO` 诊断；若无法验证关闭，它会阻断变量写入而不是冒险双写。

这次操作只切换 `mvu-auto-doctor` 自身的在线 Git 分支。不要点击数据库、骰子前端、
缝合怪、推进重roll助手或其他脚本行的分支、删除或重装按钮。

### 全新在线安装

尚未安装自动医生时，打开“扩展 → 安装扩展”，填写：

```text
仓库地址：https://github.com/magilittle0-byte/mvu-auto-doctor
分支或标签：codex/v2.0-phase7-release-candidate
```

选择“仅为当前用户安装”（单用户环境直接选择“安装”），完成后刷新页面。分支字段
不要加 `origin/`；只有从“已安装扩展”的分支列表切换时才选择带 `origin/` 的项。

## 2. 和现有脚本一起使用

数据库本体、可视化前端、骰子前端、缝合怪、推进重roll助手V2，以及其他
已经调好的脚本都可以继续启用，不需要为了测试自动医生而删除或重装。

- 自动医生只使用自己的 `mvuad-*` 控件和扩展存储，不会覆盖推进重roll助手的
  `reroll-helper-btn`、`Reroll_Global_Settings` 或 `Reroll_Cache_*`。
- 数据库只在当前回复完成修复、写后回读并进入 `settled` 后收到下游通知；
  `failed`、`stale` 或迟到任务不会向数据库、记忆、活世界或论坛写入。
- 推进重roll助手触发重生成后，自动医生会重新核对聊天、消息、swipe、
  generation、branch 和正文指纹。旧回复上的医生任务会变成 `stale`，不能污染
  新分支。
- 骰子结果、装备槽位、资源消耗和 MVU Schema 仍以角色卡与启用世界书的明确
  合同为准；自动医生不会猜字段，也不会改写骰子前端或缝合怪文件。

正常使用时可以直接点推进重roll助手。若悬浮工具页正显示任务执行中，建议先
观察该任务完成或取消后再重roll；即使直接重roll，旧任务也必须被稳定屏障拦住，
不会落到新回复或数据库里。

## 3. 日常使用

1. 正常发送消息并等待 AI 回复完成。自动医生会等待普通 MVU 更新稳定，再进行
   本地合同检查和必要的模型诊断。
2. 点击悬浮球“脉”可打开工具页；世界、事件、论坛和工具页使用同一聊天上下文。
3. 正文或变量存在可证明问题时，修复先在内存中校验，再精确写入当前楼层并回读。
   正文修正版会成为可左滑撤回的新 swipe，不会重放资源变化。
4. 危险的导演动作必须显示目标和影响范围并由你确认。没有宿主桥或证据不足时，
   页面会显示 `unresolved`，不会直接写状态。
5. 内置论坛默认手动刷新。刷新只读取已稳定的最终正文，重载页面后主题和评论应
   继续存在。
6. 工具页的操作时间线可以查看任务阶段、取消与失败原因；诊断只记录计数、
   模型、状态和耗时，不应包含私人聊天、完整提示词、密钥或原始请求载荷。

## 4. 推荐的 RC 共存测试

请用一份已备份的现有长聊天完成下面这组测试：

1. 打开1.x时期的聊天，确认旧消息、数据库状态和角色卡仍可读。
   当前候选已验证57消息、约3.17 MiB的更新前真实聊天投影；默认迁移窗口为有界
   8 MiB，超过上限会保守回退为1.x只读视图。
2. 正常生成一轮，等自动医生任务显示 `settled`，确认数据库读取的是最终回复。
3. 再生成一轮，并在医生仍在处理时使用推进重roll助手V2；确认旧任务变为
   `stale` 或被取消，新回复没有混入旧分支的正文、变量、论坛或数据库写入。
4. 检查骰子前端的结果、资源消耗和装备状态没有被重复结算。
5. 检查缝合怪、数据库可视化及其他现有脚本仍能打开，控制台没有新增错误。
6. 在手机宽度打开悬浮页和论坛，展开、收起帖子，确认没有横向溢出。
7. 刷新页面，确认聊天、数据库状态、论坛主题和评论仍然存在。

若真实结果与上述门禁不一致，请停止继续覆盖测试并按下一节提供脱敏信息；真实
环境结果优先于模拟测试，候选不能因此被放行。

## 5. 回滚到旧版

1. 取消或等待自动医生当前任务结束，并用酒馆界面保存当前聊天备份。
2. 在“已安装的扩展”中找到自动医生，点击其分叉/分支图标，选择
   `origin/main` 并确认。
3. 刷新酒馆；需要时点击自动医生这一行的“更新”，再确认扩展信息已回到 `main`
   的稳定版。不要删除原聊天、数据库、其他脚本，也不要手工删除迁移审计数据。
4. 若分支列表无法在线加载、摘要校验不一致或旧聊天不可读，停止写入并保留现场，按
   [`MIGRATION_ROLLBACK_GUIDE.md`](MIGRATION_ROLLBACK_GUIDE.md) 的保守恢复步骤处理。

## 6. 反馈问题时提供什么

可以提供：自动医生版本、SillyTavern/TauriTavern版本与提交号、手机或桌面尺寸、
是否使用重roll、可复现步骤、任务状态、控制台错误名称和脱敏诊断包。

不要提供：API 密钥、私人聊天原文、完整提示词、原始模型 payload、包含凭据的
请求头，或整个用户数据目录。
