## 产品边界

- [x] `<content>` 仍是本回合事实来源；医生不改写、截断或重生成正文，也不创建纠错 swipe。
- [x] 自动变量检查每回合只有一个主任务；手动与自动分开；旧任务、迟到、错误分支和旧 swipe 零写入。
- [x] 数据库继续独立读取 `<content>`；医生不读取数据库表、不等待数据库、不调用第三方 CRUD，也未恢复 `integrations/database-final-reply-bridge.js`。
- [x] 社交审计无效、超时、解析失败与 HTTP 失败均零写入，不执行关系回滚删除。
- [x] 论坛、连续性、人物、势力与环境属于可选后台功能，不阻塞正文、数据库或关键变量结算。
- [x] 自动医生只节制自身生成和注入的压力；正文已有过量威胁仅作为外部事实观察，不聚合、复制或升级。

## 医生闭环

- [x] Actor Ledger v2 使用稳定 ID，支持未知身份揭示合并、重复揭示合并、异变谱系、死亡/离场/休眠/唤醒。
- [x] 玩家、系统、环境、旁白与群体不会误入人物池；死亡或已解决人物不会继续调度。
- [x] 接受的 `<content>` 只反向更新人物实际观察到的信息；隐藏内心、未传播事实和第三方候选不广播。
- [x] 人物行动按候选→身份/知识/时间/地点/资源/能力/因果/玩家主权校验→结算顺序执行。
- [x] 人物、势力、环境三通道可独立推进，共享医生自己的压力与注入预算。
- [x] `due=false` 只能保留或探索，不能世界结算；收据 ID 包含完整作用域。
- [x] 收据覆盖计划→执行→世界结算→注入→正文消费/保留，并绑定聊天、消息、swipe、生成与分支身份。
- [x] 玩家设置提供后台行动人数、次要人物探索槽、势力槽、环境槽、主动碰撞强度、恢复节奏、同场压力上限、同场首领上限与注入数量，并明确只控制医生后台模拟。
