## 通用兼容边界

- 医生核心不识别或改写 TavernDB 的表名、列名、行号与 DOM；生产医生与旧桥对
  数据库公开 API 的调用数都为0。隔离 QC 只调用作者公开入口来证明数据库本体独立
  工作，不把该调用接回生产医生。
- MVU 修复以当前 `stat_data`、当前卡实际 Schema/规则、动态 JSON Pointer 和完整
  `chat/message/swipe/generation/branch/fingerprint` 身份为准，不内置当前卡路径。
- 陌生英文 `nebulaLedger` Schema 的24轮真实长局完成24/24 settled、24个不同目标
  身份和24/24真实模型成功；49条消息与24条结算记录重载后恢复。
- 装备、骰子和缝合怪识别属于保守 legacy 方言适配：只有实际文本/结构出现对应合同
  信号时才启用；未知前端继续使用通用变量修复与生命周期门，不猜槽位、资源或标签。
- 表格模板、数据库内缝合怪剧情预设、缝合怪专属显示正则、骰子前端和推进重roll
  已同时启用完成现场共存；这证明黑盒兼容与命名空间隔离，不把它扩大解释为医生
  接管或专项审计所有第三方内部语义。

## 5.5.3 卡结构兼容样本

- 原件是 PNG v3 角色卡；只读解析得到77个世界书条目、3个 TavernHelper 脚本、
  8个 regex 脚本，未发现需要医生强制接管的 TavernDB 合同。
- 旧真实卡结构计数为75个世界书条目、2个 TavernHelper 脚本。差异说明作者在卡内
  增加了内容/脚本，不等于 schema 协议改变。
- 医生现在兼容 `tavern_helper.scripts`、`tavern_helper.script.scripts`、
  `TavernHelper` 大小写变体、扁平 legacy 容器和嵌套脚本组。
- `character_version` 为空，因此兼容判断不能依赖该字段；应以 v3 数据结构、活动
  世界书与实际脚本内容字段为准。
- 卡侧建议仅为：作者可填写可读版本号，并避免同一 MVU 规则重复启用。医生不要求
  卡作者加入 barrier API，本任务也没有修改原卡。
